# P0：生产统计与流式主控接管修复

## 问题与行为

生产统计曾显示近24小时125次完成响应，其中Sider41次、兼容后端84次；兼容请求均归因为工具。Fallback为0，但保留的采样遥测中存在26条1135错误。原有“上游请求”实际主要统计已完成的客户端响应，不能代表内部登记、纠错及失败调用。

Deno主控原先默认只接管JSON，流式另需实验开关。本地现有配置还明确写了`SIDER_CONTROLLER_STREAMING=false`，仅修改默认值不足以迁移这类部署。主控开启后也必须保留XML分类和直接图文输入的兼容能力旁路。

修复后，主控默认同时接管JSON和SSE。已明确设置的false继续生效；Deno管理员可通过受鉴权策略接口保存流式覆盖值，跨实例读取同一KV配置。直接图文和XML分类使用原生兼容端；主控工具结果中的嵌套图片仍明确拒绝。

## 实现

- 新增按实际上游模型、小时聚合的调用计数，采用KV原子累加；统计与请求响应解耦，不受每实例每小时40条明细上限影响。
- 分别记录上游尝试、成功、失败、1135、已确认登记、纠错、冷却拦截、主控失败、登记待续和重放。主控分批登记的进度响应不计为业务失败。
- 在Sider客户端记录实际调用，覆盖主控、混合路由及旧Complete入口；模型窗口标签合并为基础模型。
- 主控响应重放同时更新原有缓存计数与新增调用计数，不增加上游尝试或完成响应数。
- 最近记录补充实际模型、主控／混合模式、路由原因及部署标识，并贯穿KV存取。兼容上游记录真实配置模型，Sider沿用实际发送时的模型映射；旧记录不猜测。
- 看板将原“上游请求”改称“业务完成响应”，增加独立的调用表、计数起点、遥测保留／丢弃量及有效流式开关。明细写入失败计入丢弃，不误报为保留成功。
- Deno的`POST /stats/strategy`支持布尔`controllerStreaming`，沿用既有认证；等待KV落库后返回成功。读取有3秒缓存，冷实例在路由前解析配置；保存失败返回503并保留原值。
- Node/Bun同步核心计数、路由、重放及元数据；聚合采用进程内小时桶，Deno额外提供跨实例KV持久化。
- 真实部署回归进一步发现：最后两片登记完成后继续在同一70秒请求内执行，会耗尽期限并返回502。两套运行时均在最后一批登记落库后返回待续，使执行请求获得完整期限；偶数分片测试覆盖此边界。

新增统计只从上线后开始记录，不能回填此前丢失的失败及内部调用。完成响应包含工具续轮响应，不等于整份业务任务最终完成；Sider token仍为现有字符估算，新增计数不作为供应商计费凭据。
