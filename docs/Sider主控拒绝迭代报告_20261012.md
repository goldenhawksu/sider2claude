# Sider 主控拒绝迭代报告（2026-10-12）

## 目标

针对 Sonnet 5.5 在长 Write 探测中把分片、工具定义和纠错消息判定为提示注入的问题，采用“真实探测→失败测试→最小实现→定向验证”的顺序迭代。目标不是强迫模型绕过安全判断，而是避免代理把拒绝误记为成功、避免无价值重复，并留下不含正文的诊断证据。

## 探测结论

| 探测 | 结果 | 决策 |
| --- | --- | --- |
| 现有协议 + 正常 64 行载荷 | 两段均被接收，最终返回完整 StoreContent | 保留现有正常工具契约 |
| 精确 ACK + XML/长哈希 | 首片被判定为社会工程 | 不采用 |
| 原包装 + 短固定 ACK | 首片仍被拒绝 | 不采用 |
| 现有协议 + 大量字面 `?` | 两段和执行阶段均拒绝，与附件一致 | 增加登记门禁与编码诊断 |
| “模型不执行、客户端执行”的诚实纠错 | 已拒绝的会话仍拒绝 | 明确拒绝首次熔断 |
| 生产登记判定 + 正常载荷 | 两片通过，最终返回完整 StoreContent | 判定可落地 |
| 生产登记判定 + 损坏载荷 | 首片停止 | 不再发送无效后续轮次 |
| 生产拒绝分类器 + 真实拒答 | `refusalDetected=true` | 分类器可落地 |

真实探测只使用 Sider 文本通道，`tools.auto` 为空，没有执行本地文件操作。

## 落地变更

1. 分片登记只有在回复明确包含“已记住／已接收／已收到／已记忆”等证据时才推进 `task.uploads`；否则返回 502 并停止后续分片。
2. 强制工具缺失时识别明确协议拒绝。命中后首次熔断；普通漏调允许一次纠正；JSON/schema 等其他错误保留原有两次纠正边界。
3. 主控遥测新增 `phase`、`outcome`、`correctionCount`，并记录发送前 UTF-8 字节数、字面问号数和 Unicode 替换字符数。所有新增字段均不含正文。
4. probe 客户端支持按次覆盖模型，新增 `probe-sider-controller-refusal.ts` 固化正常、损坏、ACK、纠错和熔断探测。

## 安全与兼容性

- 未放松 Write 严格 JSON、schema、正文引用和回读哈希门禁。
- 未启用 GLM/DeepSeek 自动接管主控业务回合。
- 未修改正常情况下已经通过真实探测的工具契约。
- Bun 遥测仍为 no-op，但类型与分类逻辑保持双栈一致。

## 验证结果

- `npm.cmd run test:regression` 通过：Deno 全量测试、Deno 入口及既有 probe 检查、TypeScript 类型检查、Bun 46 项单元测试全部成功。
- `npm.cmd run build` 通过，ESM、source map 和类型声明均成功生成。
- 本轮涉及的 15 个 Deno TypeScript 文件通过 `deno fmt --check`。
- 生产实现与新增 probe 通过 Deno lint；使用 `no-control-regex` 排除项是因为既有 Write 路径校验正则有意匹配控制字符。
- 完整 Deno 测试目录 lint 仍会命中旧测试文件已有的 `no-explicit-any` 和 `require-await`，本轮没有扩大范围清理这些历史问题。
- 基础真实集成回归通过 88/88，失败 0、上游受限 0；证据为 `e2e-2026-10-12T06-55-21.md`。
- Sider 主控套件 14 的 11 个用例全部取得严格通过证据：全量运行先通过 7 项，受 1135 配额影响的 4 项分别使用相同断言定向重跑并全部通过。最终大 system 用例在全新共享 KV、40 秒节奏下通过，39,111 字符 system、完整工具定义、工具选型和 `Read` 路径均正确。
- 定向运行使用 `E2E_CASE_PATTERN` 仅为公平使用上游配额而拆分测试，不修改请求、断言或通过标准；每次均要求失败 0、上游受限 0 和退出码 0。

## 剩余边界

- Sider 输出具有随机性；登记确认和拒绝识别是保守文本分类，不是上游提供的结构化状态。
- 大量 `?` 在附件中已经是字面字符；当前证据不能确定损坏发生在调用方、日志导出还是更早阶段。新增遥测只能缩小边界，不能恢复已经丢失的字符。
- 明确拒绝不会自动改走付费兼容后端。若未来启用，应使用独立配置并重新评估成本、幂等和写操作权限。
