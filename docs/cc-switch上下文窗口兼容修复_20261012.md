# cc-switch 上下文窗口与安全分类修复（2026-10-12）

## 定位依据

- 客户端先后报告 `claude-sonnet-5.5[1m]` 和基础模型名暂不可用；这不足以断言后缀是唯一原因。
- 提供的服务端请求 `req_mv560pqa_5fbd1ff6` 已是 `claude-sonnet-5.5`，含 161 条消息、27 个工具、876,170 字节，路由到兼容后端。日志仅到流开始，没有最终错误，不能据此确认三次分类失败的具体上游状态。
- 既有模型查找已支持窗口标签，但主控任务、历史、重放和冷却仍保存原请求名。五项失败测试复现标签切换导致状态分离、重复派发及续轮失败，以及直接 SiderClient 请求透传标签。
- 从本机 Claude Code 2.1.291 核对分类协议：XML 判定字段 `<block>yes/no`，部分阶段使用 `</block>` 停止序列，输出预算可为 64 token。严格 JSON 探测不属于该客户端协议，未将其作为验收标准。
- 真实 Sider XML 分类请求曾返回拒答，明确表示不会接受改变工作方式的嵌入式 system 指令。该失败与模型后缀无关，属于 Sider 文本通道无法稳定承载原生 system／分类协议。
- 确定性测试另复现显式 `thinking: disabled` 被删除，及主控接管大分类 system 后因 16 分段上限返回 413。

## 最小修复

1. 两套运行时共用相同模型规范化规则，剥离数字窗口标签并统一大小写；对 Sider 的 `model`、`chat_models` 只发送基础名，不修改调用方请求。
2. 主控历史、任务模型、重放与冷却按基础模型归一。升级前带标签的任务可通过工具 ID／cid 恢复；对外仍返回本次请求名，真正换模型仍拒绝恢复。旧的带标签缓存无需复用，按原 TTL 到期。
3. 保守冷却、自适应令牌及体量状态共用基础名，不能以改标签绕过限流；不同基础模型仍隔离。
4. 只识别无工具、system 明确同时声明分类用途与 XML 判定标签的请求，优先使用已经配置的 Anthropic 兼容后端；该路由不回退 Sider，也不消耗 Sider 令牌。业务工具请求维持原有规则。
5. JSON 与 Deno 真流式路径兑现调用方明确关闭 thinking 的要求。分类响应的内容、停止序列、实际阻止判定和错误均保留。

## 部署与边界

发布本轮代码后，cc-switch 可继续声明 1M 窗口。基础模型名与窗口标签视为同一 Sider 模型，但 Sider 的实际输入容量、分段数量及配额限制仍适用。

分类旁路要求生产已配置 `DEEPSEEK_BASE_URL`、`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`。实际后端可能是 GLM 或 DeepSeek；测试使用现有 Z.ai GLM 配置。上游限流、拒绝或不可用仍交回客户端，代理不能承诺任何时候都允许 Bash。

推送提交与生产部署是不同步骤。应通过生产部署版本和 `rule_0_safety_classifier` 日志确认新代码生效；本文记录的补充日志不能独立证明此前三次分类失败的唯一原因。
