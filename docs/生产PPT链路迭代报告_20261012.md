# 生产 PPT 链路迭代报告（2026-10-12）

## 输入证据

ppt-master 使用生产 Sider2Claude 作为 Claude Code provider 时，运行停在资料获取阶段：

1. Bash 安全分类器报告 `claude-sonnet-5.5[1m]` 临时不可用。
2. `fetchGithubReadme` 返回仓库不存在，WebFetch 随后成功获取仓库页面。
3. Z.ai 内置 `webReader` 成功读取 `README_CN.md`，但读取中文 docs 路径时连续返回
   `MCP error -400: Please Enter the Correct URL Format`。
4. 日志没有进入模板解析、页面生成或 Write 阶段。

## 探测与结论

| 探测 | 结果 | 结论 |
| --- | --- | --- |
| 严格查找 `claude-sonnet-5.5[1m]` | `getModelById` 返回 undefined，普通映射却返回基础模型 | 主控与普通路由不一致，需修复 |
| 主控 HTTP 装饰模型 | 修复后上游收到 `claude-sonnet-5.5`，对外仍为 `[1m]` | 模型兼容修复有效 |
| raw 上游，不声明网页工具 | 模型说明没有 webReader，正常 `end_turn` | 内置工具不是无条件能力 |
| raw 上游，声明客户端网页工具 | 两个内置 webReader 均 -400，随后产生客户端 MCP `tool_use` | 上游能降级，但浪费两轮工具尝试 |
| adapter 端到端 | 输出 `thinking + tool_use:mcp__webReader__read`，`stop_reason=tool_use` | 代理没有吞掉客户端工具 |
| raw 上游，提示优先客户端网页工具 | 直接产生客户端 MCP `tool_use`，无 `server_tool_use` | 条件提示可落地 |

## 落地变更

1. 模型查找和映射统一剥离末尾数字上下文窗口标签，例如 `[1m]`、`[200k]`；不接受
   `[beta]` 等非窗口标签，不增加公开模型目录条目，也不改变对外响应模型名。
2. 当客户端工具名包含 `webReader` 或 `WebFetch` 时，在稳定 system 前缀中追加一条指令：
   不使用服务端内置 webReader，直接输出声明的客户端网页工具 `tool_use`。
3. 保留现有服务端工具转换和结束语义。真实 adapter probe 已证明最终客户端工具块和
   `tool_use` 结束原因完整，无需自动伪造续轮。
4. 新增 `probe-server-tool-continuation.ts`，可观察 raw SSE 与 adapter 结果，不保存网页正文。
5. 对用户明确要求“逐字／原样／exact”的 Write 增加严格恢复：仅接受同时包含“目标路径”、
   “正文开始”和“正文结束”的原始用户消息，且模型必须只选择一个 Write。路径和正文直接取
   用户原文，不猜测、不补写；日志只记录字符数及路径是否变化。

## 未在代理中处理的事项

- `fetchGithubReadme` 对仓库 URL 的业务误判属于具体 MCP 工具行为；代理不能伪造 README。
- Z.ai 内置 webReader 的 URL 规则无法通过百分号编码可靠修复，因此不在代理内猜测改写 URL。
- Bash 安全分类器仍可能因 Claude Code 客户端或上游瞬时状态不可用；本轮只消除了
  `[1m]` 在 Sider2Claude 主控入口被确定性拒绝的问题。
- 本轮日志没有到达 PPT 写入阶段，因此此前的多行 Write 修复和主控长正文修复未被再次触发。

- 真实 `AnthropicApiAdapter`：最终保留 `tool_use:mcp__webReader__read`，结束原因为 `tool_use`。
- 主控 HTTP：`claude-sonnet-5.5[1m]` 对上游映射为基础名，对外响应保留装饰名。
- `npm.cmd run test:regression` 通过，Bun `46/46`；Deno 全量测试、入口检查、类型检查均通过。
- 生产构建、相关文件格式检查、生产代码 lint 和 `git diff --check` 通过。
- 基础真实集成回归通过 88/88，失败 0、上游受限 0；其中包含 17 工具的 PPT 资料循环、
  51 条历史消息与 18 个工具，以及长 JSON Write 完整性。
- 长 JSON Write 套件在修复后连续通过；确定性测试同时覆盖多行严格 JSON 与显式逐字边界恢复，
  非严格或不完整 Write 仍会阻断整轮工具执行。

  schema 分段后正确调用 `Read`。
- 受 Sider 公平使用配额影响，主控套件使用 `E2E_CASE_PATTERN` 拆分运行；该过滤只选择用例，
  没有放宽任何请求或断言，每个补跑用例均为通过 1、失败 0、上游受限 0。
