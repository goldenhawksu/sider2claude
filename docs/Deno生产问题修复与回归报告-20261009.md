## 修复内容

### 1. 跨 `cid` 响应缓存隔离

主控响应重放键原来只包含认证主体和请求体。不同会话发送相同续轮正文时，后一个会话会命中前一个会话的缓存。

修复后缓存键同时包含规范化 `session/cid` 和请求体：

- 同一会话、同一请求仍可幂等重放。
- 不同会话即使请求体完全相同，也使用不同缓存键。
- 旧缓存键与新结构自然隔离，不会继续命中旧值。

新增测试建立 A/B 两个会话，用完全相同的续轮正文请求，分别断言自己的标记和会话 ID。单元与真实集成均通过。

### 2. 生产策略与原始遥测鉴权

- `POST /stats/strategy` 现在使用现有 `requireAuth` 中间件。
- `GET /stats/telemetry.json` 现在使用相同认证保护。
- 统计页面切换策略时从当前浏览器 `sessionStorage` 读取管理凭证；首次操作时询问，401 后清除失效凭证。
- 凭证不写入 HTML、不进入 URL，也不持久化到跨会话存储。

### 3. CORS 与响应安全头

全局 CORS 现在允许实际客户端所需头部：

- `X-API-Key`
- `Anthropic-Version`
- `Anthropic-Beta`
- `X-Conversation-ID`
- `X-Parent-Message-ID`
- `X-Request-ID`

同时暴露会话、请求和路由诊断响应头。响应补充 `nosniff`、`DENY` frame policy、no-referrer、Permissions Policy、HSTS，并在路由未自行指定缓存策略时使用 `Cache-Control: no-store`。

生产验证 workflow 已升级为真实预检：除 204 外，还必须断言 `x-api-key` 与 `anthropic-version` 出现在允许头列表。

### 4. 畸形 JSON 错误分类

`POST /v1/messages` 在规范化请求前单独捕获 JSON 解析失败，现在返回：

- HTTP 400
- `type=error`
- `error.type=invalid_request_error`
- `message=Invalid JSON body`

不再把客户端语法错误归类成可重试的 HTTP 500。

### 5. 确定性测试隔离

本机生产 `deno/.env` 曾改变测试中的主控、fallback、模型和 KV 语义，导致同一代码在 CI 与本地得到不同结果。

修复后：

- Deno 与 Bun 两套环境适配器都识别 `S2C_DISABLE_DOTENV=true`。
- `deno task test` 显式禁用 dotenv，并被 `deno task regression` 和 npm 脚本复用。
- Bun 测试通过 preload 设置隔离标志。
- Bun 测试显式串行执行；这些测试会替换全局 fetch 和环境变量，不具备并发隔离条件。

在生产 `.env` 仍存在的工作区中，Deno 回归由之前的污染失败恢复为 324/324，Bun 回归恢复为 39/39。

### 6. 集成断言稳定性

Anthropic、OpenAI 和 Gemini 的 system 测试原先要求模型添加固定前缀。真实模型偶尔把这种提示判断为格式劫持并拒绝，导致协议正确但测试失败。

新用例由 system/systemInstruction 提供随机确认码，用户再询问确认码。没有 system 内容就无法知道该值，因此仍严格验证协议转换，同时不依赖模型是否愿意遵循格式强制。

## 中间失败说明

测试过程中曾出现 Sider 1135 配额限制和一次 GLM TLS 连接瞬断。它们发生在连续多轮全量真实上游调用后，不属于本次代码回归。最终门禁通过以下方式降低噪声，但没有放宽断言：

- 将混合路由和 Sider 主控拆成语义明确的两套矩阵。
- 混合路由矩阵优先兼容后端，减少重复消耗 Sider 配额。
- `E2E_REQUIRE_ALL_PASS=true` 保持开启，最终报告不接受 upstream 状态。
