# 后台工具结果检查点恢复修复

## 问题与定位

生产客户端的 PowerShell 生图命令已返回后台任务 ID 和输出路径，下一轮却收到：

```text
400 invalid_request_error: 工具结果没有可恢复的主控检查点
```

追加“请继续完成”仍然失败。该错误由两套 `utils/sider-controller.ts` 的
`resolveTask` 抛出，发生在请求 Sider 之前，与生图后端配置、manifest 内容无关。

根因有两处：

1. 主控依赖本地工具映射、会话或历史索引，遇到旧后端产生的工具历史或过期检查点时，
   即使客户端带有完整工具调用及结果，仍直接拒绝续轮。
2. 历史查找仅移除最后一条消息。工具结果之后追加一条用户指令时，查找内容会包含
   工具结果，无法命中原助手响应对应的检查点。

推送前使用合成 PowerShell 历史在旧生产版本验证：Opus 5.5、Sonnet 5.5 各一项，
两项都返回上述同一条 400；没有启动实际命令或生成图片。

## 修复行为

- 以最近助手轮结束的位置查找历史检查点，保留后续全部工具结果和用户指令。
- 优先复用原任务及真实 Sider 会话；只有检查点确实缺失时，才从最近助手轮完整且唯一
  配对的调用与结果创建新任务，将完整客户端历史交给新的 Sider 会话。
- 保留工具参数、结果正文、错误标记、后台任务 ID 和输出路径，并补回当前调用者的工具映射。
- 明确提示模型根据已有后台任务继续查询；已有结果的命令不能重新执行，后台启动也不能当作任务完成。
- 相同请求沿用响应重放机制，恢复后的新工具继续关联新检查点。
- 重复、错配、缺失结果及孤立工具结果仍返回 400；已有任务的会话冲突、跨任务归属、
  已处理结果和模型切换校验继续生效。

两套运行时逻辑同步。恢复不会读取其他调用者的状态，也不会重建已经失效的可信正文引用或写入校验凭据。
客户端未携带完整配对历史时，仍需拒绝恢复，不能猜测工具是否执行过。
